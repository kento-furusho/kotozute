# web/

`kotozute.app` に置く静的ページ。App Store の審査で URL を求められる。

- `terms.html` … 利用規約
- `privacy.html` … プライバシーポリシー

## 差し替え済みの値

| | |
|---|---|
| 運営者 | 古庄健人（Kento Furusho） |
| 連絡先 | support@kotozute.app |

運営者名にローマ字を併記しているのは、Apple の開発者登録名が `kento furusho` で、
個人アカウントではこれが App Store の販売者名としてそのまま表示されるため。
漢字だけだと表記が食い違って見える。

連絡先は Cloudflare Email Routing で Gmail へ転送している。
`noreply@kotozute.app` は SES の送信元なので、問い合わせ先には使わない。

## 公開先

Cloudflare で配信する。リポジトリ直下の `wrangler.jsonc` が、このディレクトリを
そのまま配信する設定になっている。

いまのダッシュボードは Git 連携で **Pages ではなく Worker を作る**（デプロイ コマンドが
`npx wrangler deploy` になる）。そのため「静的アセットのみの Worker」として置いている。
コードは無く、`assets.directory` に `./web` を指すだけ。

公開後の URL は **`.html` を付けない**。Cloudflare の静的アセット配信は
`.html` 付きのリクエストを拡張子なしへ 307 で正規化するため、付けると
毎回リダイレクトを挟むことになる。

- `https://kotozute.app/terms`
- `https://kotozute.app/privacy`

ページ同士のリンクも拡張子なしで書く。

`main` に push すると自動でデプロイされる。**ページを直したら本番に出る**ので、
下書きのまま push しない。

## 注意

**法律の専門家による確認は受けていない。** 実装の事実に沿って書いた草案なので、
配布前に内容を確認すること。とくに免責は、事業の形（個人／法人）で変わる。

専属的合意管轄の条項は置いていない。Apple の審査で求められるものではなく、
個人向けアプリで運営者の地元を専属管轄にすると消費者に不利とみなされ、
裁判所の判断で移送されることもあるため。必要になったら足す。

内容はコードの実装と対応している。**実装を変えたらここも直す。**
とくに次の3点はアプリ固有の約束なので、食い違うと問題になる。

- ことづてが相手に見える条件（相互ロック）
- オープン済みのことづては編集も取り消しもできないこと
- アカウント削除で相手のことづては消えないこと
